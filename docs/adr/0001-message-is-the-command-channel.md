# ADR-0001 · 指令走消息，不走远端 shell

状态：已采纳（2026-11-09）

## 背景

需求原文是"跨端 agent 会话支持互相调用命令"。这句话至少有两种读法：

1. 在对方机器上**执行** shell 命令，拿回 stdout；
2. 把一段指令**投递**给对方的 agent，由它自己的会话、它自己的权限去执行。

## 决策

只做第 2 种。`peer_ask` 把一段文字投进对端的跨端会话，同步等对方的 agent 答完。
本插件**不提供**任何远端 shell 执行入口，也不暴露远端终端。

## 理由

- 第 1 种等于在对方机器上开一个本插件自己的 shell，它绕过对方 agent 的判断、对方的沙箱策略和对方的人。DSH 的沙箱与审批都是围绕"会话内的 agent 动作"设计的，绕过去之后没有任何一层还在起作用。
- 第 2 种把"要不要做、怎么做"留在对方：对方的系统提示、对方的权限模式、对方的人（`confirm` 模式下）。风险与控制点都在正确的那一侧。
- 第 2 种天然可审计：投递的是一段文字，不是一串副作用。审计里能读出意图；shell 调用只能读出 argv。

## 后果

- 跨端延迟 = 对方一次 agent turn 的时间（秒到分钟），不是毫秒。工具描述必须写明这一点，否则调用方会当它是 RPC。
- 对方 agent 不听话时，"命令没执行"和"执行错了"在语义上无法区分——这被接受：这是 agent 的特性，不是缺陷。
- 如果将来确实要远端执行，它必须是**独立的一个插件、独立的一次放行、独立的一种权限**，不能长在这个插件的权限模式里。
