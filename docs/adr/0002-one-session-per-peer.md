# ADR-0002 · 一条连接一个跨端会话

状态：已采纳（2026-11-09）

## 背景

对端发来一条指令，本机的 agent 要在某个会话里执行它。候选：

- (a) 每条连接一个专用会话，标题 `跨端 · <对端名>`；
- (b) 投进本机"当前活跃"的会话；
- (c) 由发送方指定本机的会话 id。

## 决策

(a)。一条连接固定对应一个跨端会话，首次需要时才创建（冷启动）。
(c) 保留为 `peer_ask` 的可选参数（知道 id 就能指定），默认走 (a)。

## 理由

- 隔离：跨端指令不会插进人正在写的代码会话里，也不会把人的上下文顶掉。
- 可读性：「这个对端让我干过什么」= 打开那一个会话，不需要检索。
- 成本可控：一条连接的历史是一个会话的历史，压缩、归档、清空都有现成的入口。
- (b) 会把消息塞进错误上下文——对端并不知道本机此刻在干什么。
- 只做 (c) 要求发送方知道接收方的内部状态，耦合太深，且容易打错。

## 后果

- 每条连接多一个会话（`confirm` 模式下第一次同意消息时才创建，不是放行时就建）。
- 会话标题要跟着显示名变；改名要同步改标题（或接受旧标题，MVP 接受旧标题并在 README 写明）。
