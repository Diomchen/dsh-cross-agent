# ADR-0003 · 抄一份传输层，不抽共用底座

状态：已采纳（2026-11-09）

## 背景

`dsh-zoo`（同一作者，`/Users/gensean/sean_project/test/local-pet`）已经实现了"局域网 DSH 实例互相发现 + 放行 + 传文件"，
形态与本插件要的几乎同构：UDP beacon 发现、`deviceId` 认人、`peers.json` 放行名单、TCP 传文件、回执、限流。
可选：

- (a) 抄一份发现/放行进本插件，各自独立演进，端口错开；
- (b) 抽出 `dsh-lan-peer` 底座包，两个插件都依赖；
- (c) 读 `dsh-zoo` 的 `peers.json`，共用放行名单。

## 决策

(a)。端口错开：本插件用 `45881/udp`（发现）与 `45883/tcp`（RPC 与文件）；`dsh-zoo` 保持 `45871/udp` 与 `45873/tcp`。

## 理由

- 共通部分只剩"UDP 发现 + deviceId + 放行队列"约 300 行；ADR-0001 砍掉远端 shell 之后，文件传输的语义（回执、收件箱、限流）也已经分叉。
- (b) 会把 `dsh-zoo` 的发布节奏和本插件绑死；`dsh-zoo` 正在活跃开发（v1.2），一次破坏性重构的代价大于 300 行重复。
- (c) 是事故：`dsh-zoo` 的"放行"含义是"能来串门"，本插件的"放行"含义是"能给你的 agent 下指令"，风险等级差一个数量级。共用一个名单意味着装个宠物的同时把指令通道也开了。

## 后果

- 两份发现代码会各自修 bug；接受。若要收敛，等本插件稳定后单独做一次移植，而不是在开发期抽底座。
- 同一台机器上两个插件的 UDP 端口不同，互不干扰；`reuseAddr: true` 让同一机器上的两个 DSH 实例也能共用端口（本地端到端测试依赖这一点）。
